# RITAS

실험 PC에서 생성된 결과 bundle을 Edge 서버로 전송하고, 장비별 전처리와
로컬 LLM을 이용해 실험 결과 보고서를 자동 생성하는 프로젝트이다.

## 구성

| 경로 | 설명 |
|---|---|
| `edge_api_server/` | 파일 수신, 보고서 요청, FT-IR/Raman/XRD 웹 분석 FastAPI 서버 |
| `common/` | 공통 환경 설정과 Plotly 스타일 모듈 |
| `config/` | 개발·운영 환경 프로파일 |
| `sune/` | FT-IR 전처리 및 보고서 생성 로직 |
| `lim/` | XRD 전처리 및 시각화 도구 |
| `ahn/` | AHN 실험장비 프로젝트 영역 |
| `rin/` | RIN 실험장비 프로젝트 영역 |

`RitasAxApp/`는 현재 실제 운영 대상이 아니며, 프로젝트 파악과 문서 기준에서는
`sune`, `lim`, `ahn`, `rin` 네 영역을 활성 프로젝트로 본다.

Raman raw 업로드, 축 고정, 비율 라벨 개별 편집 사용법은 [Raman 사용 안내](rin/README.md)를 참고한다.
Raman 텍스트 raw는 UTF-8/CP949 및 BOM이 있는 UTF-16/UTF-32를 지원하며,
CRLF·LF·CR 줄바꿈과 한 파일 안의 여러 시료를 미리보기·보고서에서 함께 처리한다.

FTIR/Raman 측정 그래프는 **Raw 원본 X·Y 값**을 선형으로 연결한다. 표시선에는
정규화·평활화·베이스라인 보정·공통 그리드 보간을 적용하지 않으며, 측정 범위 밖으로
0 또는 끝값을 채우지 않는다. 피크 검출용 전처리와 표시 데이터를 분리한다.
여러 시료도 기본은 원본값 중첩이며 `스택`/`Y 이동`을 선택한 경우에만 수직 이동한다.
`Origin 스타일`은 서식 변경이지 데이터 변환이 아니다. 기존 결과는 재분석해야 적용된다.

FTIR/Raman의 **그래프 도구 → 축 범위 및 눈금 설정 → 그래프 크기**에서 최대 폭
(320~2400px, 빈칸은 화면 너비)과 `자동`·`4:3`·`16:9`·`1:1` 비율을 선택할 수 있다.
예: 폭 `1000`, 비율 `4:3` → `크기 적용`. 비율은 축·범례를 포함한 전체 이미지 기준이며
Raw 값과 축 범위는 유지한다. 화면이 좁으면 폭을 줄이고 최소 높이를 확보하지만 저장
이미지는 선택한 비율을 유지한다. `자동 크기`로 복원할 수 있다.

네 실험 화면의 **보고서 전송 정보**에서 의뢰번호를 조회·선택하거나 직접 입력할 수 있다.
직접 입력하는 경우 전송에 필요한 실제 LIMS 실험코드도 입력해야 한다. 조회 후 의뢰번호를
바꾸면 이전 의뢰의 상세 정보와 자동 입력된 실험코드 연결을 해제하므로 다시 확인한다.
수동 입력은 LIMS 등록 여부 확인을 대신하지 않으며, 기존 프로젝트 접근권한·보고서 전송
권한·최근 SSO 인증 요건은 동일하게 적용된다.

그래프와 라이브러리의 색상 버튼은 공통 웹 팔레트를 사용한다. FTIR/Raman의 범례·피크 그룹·
도형(글자/선/배경)·피크 라이브러리와 XRD의 범례·상 그룹에서 **80색 기본표**, 최근 사용
10색, HEX 코드, 색조·채도·명도 조절을 제공한다. 기본표는 클릭으로 선택하고 직접 조절한
색은 `적용`으로 선택한다. 범례의 `전체 저장`, 라이브러리의 `저장` 등 기존 확정 절차는
유지한다. 팔레트는 외부 통신 없이 동작하며 새로 생성하는 오프라인 그래프 HTML에도 포함된다.

## FTIR/Raman 작업 템플릿 파일

실험 화면의 **작업 템플릿**에서 이름을 입력하고 **템플릿 저장**을 누르면
`*.rist-template.json` 파일을 다운로드한다. 다른 RAW를 업로드한 뒤 **템플릿 불러오기**로
적용하거나, 빈 작업에 템플릿을 먼저 불러온 뒤 RAW를 추가할 수 있다.

- 저장: 피크 민감도, 피크 라이브러리 선택, Origin 스타일, 시료 순서별 선 색/굵기/종류,
  스택 사용/간격, FTIR 흡광도/투과도, 그래프 폭/비율, 축 눈금/고정, 범례 서식과 피크 표시,
  공통 실험조건. 축 범위와 제목(빈 제목 포함)은 체크한 경우에만 저장한다.
- 제외: RAW 자체, 시료명, 수동 추가/삭제/이름 변경 피크, 박스/주석, 비율 결과, 개별 Y 이동,
  의뢰번호·SSO·보고서/AI 해석·시료별 조건. 분석 결과를 다른 시료에 복사하지 않는다.
  Raman의 RAW별 자동 수집 정보가 포함된 세부조건 원문도 제외한다.
  새 RAW에서 피크를 다시 검출하며 스택 간격도 새 데이터의 크기를 기준으로 계산한다.
- 현재 RAW에 불러오면 확인 후 수동 편집을 초기화하여 다시 분석한다. 실패 시 기존 그래프와
  설정을 복원한다. 기존 완료 보고서는 템플릿 적용 후 다시 생성해야 전송할 수 있다.
- 적용 중인 템플릿은 RAW 재분석에도 사용된다. **자동 적용 해제**는 현재 그래프를 유지하고
  이후 자동 서식 적용만 중지한다. **초기화**는 적용 중인 템플릿도 해제한다.
- FTIR/Raman 간 교차 적용은 막는다. 다른 PC/서버에서도 사용할 수 있지만 선택한 라이브러리의
  동일 ID가 해당 서버에 필요하며 **현재 등록된 라이브러리 내용**으로 재분석한다.
  누락된 라이브러리는 안내 후 적용을 중단한다. 파일은 최대 256KB, 서버 업로드 없이 읽는다.
  공통 실험조건은 재사용한 값이므로 새 실험과 일치하는지 확인한다.

## FTIR/Raman 보고서 검토와 수신자용 보고서

실험 화면의 **보고서 미리보기**는 작성자용 편집 화면이다. 의뢰번호·실험코드·실험장비·실험자와
실험조건/환경을 확인하고, 빈칸과 AI 해석·표·메일 문안을 직접 수정할 수 있다. 미입력 항목도
보고서에 빈 행으로 포함한다. `수정 내용 저장 및 미리보기 갱신`을 누르면 LLM을 다시 호출하지 않고
수정한 PPT/PDF/HTML ZIP을 새 보고서 ID로 생성한다. 기존 발행본과 전송 대기 파일은 덮어쓰지 않는다.
저장 전에는 다운로드·전송을 막으며, 저장 후 편집 화면과 열려 있는 원래 분석 화면은 수정본을 사용한다.
SSO 실험자를 포함한 전송정보가 보고서와 다르면 전송을 막고 수정·저장을 안내한다.
로그인 사용 시 작성자 또는 관리자만 편집할 수 있다. 서버 재시작/임시 작업 만료 후에는 보고서를 다시 생성한다.
DB 스키마 변경은 없다. 아래의 수신자용 HTML에는 편집 기능이 포함되지 않는다.

그래프의 피크·이름·박스·메모 편집을 마친 뒤 보고서를 생성하면, **보고서 미리보기 → 분석 결과**에서
로컬 LLM의 해석 초안을 확인한다. 생성 시점에 남아 있는 피크의 위치·강도·수동 추가 여부와
박스 관심 영역, 메모, Raman 비율을 근거로 사용하며 삭제한 피크나 편집 전 판정은 재사용하지 않는다.
같은 문안이 PPT/PDF에도 반영된다. AI 해석은 분석자의 검토가 필요하며, 연결 실패나 일부 생성 시에는
규칙 기반 요약과 구분해서 표시한다. 그래프 자체를 수정한 경우에는 보고서를 다시 생성해야 해석이 갱신된다.

`PPT 페이지` 탭에서 실제 PPT를 변환한 페이지를 한 장씩 확인한다.
전송·다운로드 ZIP의 `report.html`도 같은 미리보기이며, 인터넷 연결 없이 열린다.
`인터랙티브 그래프`는 발행 당시의 좌표·피크·라벨을 보존하고 확대/축소·이동·시료 숨김과
`발행본/중첩/스택` 보기만 제공한다. 피크 추가·삭제, 민감도·비율·라벨·해석 편집이나
결과 저장 API는 포함하지 않는다. 분석자 작업 화면의 편집 기능은 그대로 유지한다.

새 보고서를 생성해야 적용된다. 기존 정적 본문은 `report-summary.html`로 함께 제공한다.
이 보호는 열람용 UI의 결과 편집을 막는 방식이며, 다운로드한 PPT/HTML을 외부 도구로
수정하는 것까지 막는 DRM은 아니다. 서버 배포 후 브라우저를 새로고침하고 보고서를 재생성한다.

## Edge API 실행

Python 3.11 이상이 필요하다.

```bash
cd edge_api_server
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

export RIST_ENV=development
python -m app.run
```

브라우저에서 `http://127.0.0.1:8000/ftir`을 열면 DPT 파일을 선택하거나
드래그 앤 드롭해 전처리·피크 분석 결과를 바로 확인할 수 있다. DPT의 파수·강도
2열은 쉼표, 탭 또는 공백 구분을 지원하며 미리보기와 보고서에 동일하게 적용된다.
재료별 피크 assignment 라이브러리는 여러 개를 동시에 선택할 수 있으며 화면에서 JSON/CSV
파일을 가져오거나 편집창에서 직접 생성·수정할 수 있다. 기본 설치 시 일반
작용기표와 함께 590개 기준 FT-IR 스펙트럼에서 추출한 카테고리별 marker 피크
라이브러리가 제공된다. 라이브러리 삭제는 기본 비활성이고
`RIST_FTIR_ASSIGNMENT_LIBRARY_DELETE_ENABLED=true`로 설정한 뒤 Edge API
서비스를 재시작하면 사용할 수 있다.

보고서 worker는 별도 프로세스로 실행한다.

```bash
cd edge_api_server
source .venv/bin/activate
export RIST_ENV=development
python -m app.report_worker
```

자세한 내용은 [Edge API README](edge_api_server/README.md)를 참고한다.

폐쇄망 Edge의 HTTPS는 [자동 설정 스크립트](edge_api_server/deploy/setup_https.sh)로
구성할 수 있다. 사내 인증서 적용 또는 별도 관리 PC의 내부 CA/CSR 발급, 기존 설정
백업, Nginx/보안 쿠키 설정, 실제 TLS 검사, 실패 시 복원을 지원한다.
기본 주소는 `https://10.10.1.31`이며 Python의 8000 포트는 내부 전용으로 전환한다.
패키지 반입·방화벽 허용·실험 PC/C#의 주소 및 CA 신뢰 등록은 별도이며,
[HTTPS 배포 절차](edge_api_server/deploy/README.md#폐쇄망-https-자동-설정)를 따른다.

## 웹 브라우저 지원 정책

- 모든 웹 UI의 기본 지원·최적화·검증 기준: **Supermium 144 안정판 + Windows XP·7·10·11**.
  별도 요청이 없어도 이 기준을 적용하며, 저사양·고사양 PC를 모두 고려한다.
  XP SP3 32비트의 재현 기준 빌드는 **144.0.7559.256 R5 32비트**이며, 각 OS의
  현장 설치본과 세부 빌드에 맞춰 별도로 확인한다. 기준 지정만으로 네 OS 모두의
  실기 검증 완료를 의미하지 않는다. 개발 작업에도 [브라우저 작업 지침](AGENTS.md)을 적용한다.
- 보안 지원 중인 OS의 최신 Chrome·Edge는 주요 기능 호환 확인 대상으로 유지한다.
  Windows 업무 PC는 Windows 11을 권장하며, 브라우저 이름만으로
  다른 브라우저를 강제 차단하지 않는다.
- 모바일의 기존 반응형·터치 동작은 유지하며 Android Chrome과 iOS Safari/Chrome의
  실제 업로드·스크롤·다운로드 동작은 별도로 검증한다.
- XP 장비의 **Chrome 49.0.2623.75**를 호환 기준으로 둔다. Chrome/Chromium 49~109와
  EdgeHTML에는 서버가 미리 빌드한 ES5 코드·파일/통신/포인터 폴백·호환 CSS를 전달한다.
  최신 브라우저에는 기존 코드를 그대로 전달하며 호환 번들을 추가로 로드하지 않는다.
- **Supermium 144/150**은 네이티브 화면·그래프·포인터 기능을 유지한다. 브라우저 호환성과
  전송 성능 정책을 분리하여 Supermium/Chrome 및 OS 이름과 관계없이 메모리·CPU 정보로
  TEM 전송 크기를 선택한다. Chrome으로 위장된 경우에도 같은 기준을 적용하며, `/tem?browser=supermium` 또는
  `/ftir?browser=supermium`으로 이 PC의 설정을 명시할 수 있다. 설정은 같은 사이트의
  다른 실험 화면에도 유지되며 `?browser=auto`로 해제한다. Chrome 49 호환 자산을
  강제로 우회하지는 않는다. 실제 XP/Supermium 실기 검증과 UA 모의 검증은 구분한다.
- IE는 분석 화면 지원 대상이 아니다. XP/구형 브라우저의 보안 지원을 복원하는 기능이
  아니므로 격리된 실험망에서만 사용한다. TLS·인증서·SSO 보안은 약화하지 않는다.

로그인·가입에는 실험실 브라우저 기준을 안내하며, 첫 화면에는 고정된 Chrome 권장
문구를 표시하지 않는다. 네 실험 화면과 계정·운영·보고서 검토
화면은 알려진 구형 환경 또는 필수 기능 누락을 감지하면 안내를 표시한다.
안내는 경고일 뿐 인증·권한을 바꾸거나 API/C# 전송·보고서 다운로드를 차단하지 않는다.
경고가 없다고 최신 버전 또는 모든 기능의 검증 완료를 보장하는 것은 아니다.

`/login`과 `/signup`은 JavaScript 없이 동작하는 HTML POST 양식이다. 구형
브라우저에서도 서버가 입력 검증과 오류 안내를 처리하며, 쿠키와 동일 출처 요청
확인이 필요하다. 기존 JSON 인증 API와 가입 승인·프로젝트 권한·SSO 정책은 유지한다.

Chrome 49 호환 자산은 FTIR·TEM을 포함한 실험 화면, 계정·회원·VOC·운영 화면에
적용한다. 생성·분석·OCR·보고서 작업은 기존 서버에서 수행하며, 파일 업로드는 기존
청크·무결성 검사 경로를 유지한다. 구형 OS의 TLS/인증서 오류는 별개이므로 HTTPS나
인증서 검증을 약화하지 않는다. 상세 배포·점검 방법은
[웹 인증 명세](documents/EDGE_WEB_AUTH.md#10-로그인회원가입의-구형-브라우저-호환성)를 참고한다.

TEM 대량 업로드는 브라우저가 보고하는 메모리 **4GB 초과·논리 CPU 2개 초과**가 모두
확인되면 **4MiB 순차 전송·목록 500개**, 그 외 또는 어느 한 정보라도 없으면
**2MiB 순차 전송·목록 200개**를 사용한다. 이는 접속 시 자원 힌트에 따른 정책이며
실시간 여유 메모리 측정이나 모든 기능의 자동 성능 조절은 아니다.
체크섬은 256KiB씩 계산하면서 UI에 실행 시간을 돌려준다(목록에서 생략된 파일도 모두 업로드).
ZIP/조각 검증은 서버의 임시 디스크를 사용하며,
웹의 무결성 검사와 보고서 생성은 기본 1개씩, 대기 4개까지 처리한다.
ZIP 해제 후 합산 용량·파일 수·이미지 픽셀·디스크 여유 공간도 검사한다.
한도를 초과하면 묶음을 나누어야 하며 모든 규모에서 메모리 부족을 방지한다는 보장은 아니다.
[TEM 제한·설정](edge_api_server/README.md#temstem-웹-보고서)을 참고한다.

TEM 파일/폴더 드롭은 이벤트 안에서 파일 핸들을 확보한 후 순차적으로 목록을 읽는다.
폴더 선택창을 여는 동안은 처리 중으로 잠그지 않으며, 선택 완료 후에만 목록 준비 상태를
표시한다. EDS DOCX는 여러 파일의 개별 첨부와 하위 폴더 검색을 지원한다. 파일명만 같은
문서의 이미지가 반복되는 캐시 충돌도 방지한다. 이 변경은 Supermium 144를 기본 기준으로
적용하며, Windows 7 실기 검증 여부와 서버·자동 회귀 테스트 결과는 별도로 구분한다.

호환 자산은 `edge_api_server/app/static/chrome49/`에 커밋되어 폐쇄망에서 CDN/Node 없이
실행된다. UI JavaScript/CSS를 수정하면 [호환 빌드 안내](edge_api_server/browser_compat/README.md)에
따라 재빌드하고 함께 배포한다. 실제 XP Chrome 49.0.2623.75 현장 검증과 최신 Chrome에서
구형 API를 제거한 대체 검증은 구분한다. UA만 변경한 시험은 실기 검증이 아니다.

2026-10-10에는 실제 XP SP3 32비트 VM에서 Chrome 49.0.2623.75와 Supermium 150 R2로
가입·로그인, FTIR 분석/그래프/PNG·ZIP 저장, 약 30MiB TEM 청크 업로드/보고서, 계정·VOC를
검증했다. 다운로드 ZIP 4개는 원본과 바이트 단위로 일치했다. 다만 XP 커널 재시작 1회는
원인 미확정이며 운영 HTTPS·SSO·LIMS 검증은 별도다.
[실기 결과·한계·VM 재실행](edge_api_server/browser_compat/README.md#실제-windows-xp-vm-실기-검증-2026-10-10)을 참고한다.

구형 장비 PC의 전송 프로그램은 별도 검증 대상이다. 저장소의 C# 참조 예제는
`.NET 8`용이며 XP/Windows 7 운영용이 아니다. 실제 프로그램의 OS·런타임·TLS
지원 또는 최신 전송 중계 PC 사용 여부를 C# 개발자와 확정해야 한다.

## 실험별 VOC 게시판

FT-IR, Raman, XRD, TEM 화면의 **VOC · 의견 보내기** 버튼으로 해당 실험의
게시판을 별도 탭에서 연다. 분석 화면의 파일과 그래프 편집 상태는 유지된다.
통합 게시판은 `/voc`이며 운영 관리 메뉴에서도 접근할 수 있다.

- 일반 회원은 현재 승인된 실험의 모든 VOC와 관리자 조치 이력을 함께 조회한다.
  다른 실험의 글은 조회할 수 없으며, 해당 실험 권한이 회수되면 본인 글도 조회할 수 없다.
- 관리자는 네 실험 전체를 실험·상태·검색어로 조회하고 조치 내용을 작성한다.
- 처리 흐름: **접수 → 조치 중 → 조치 완료 → 작성자 확인 완료**.
  조치 완료에는 조치 내용이 필수이며, 마지막 확인 체크는 작성자 본인만 할 수 있다.
- 등록·조치·확인 이력을 MariaDB에 보관한다. 작성자 확인 후에는 상태를 수정하지 않는다.
  별도 SSO 인증은 필요하지 않으며 기존 로그인과 실험별 권한을 사용한다.
- 현재 범위는 텍스트 VOC와 처리 이력이며 첨부파일·댓글·메일/푸시 알림은 포함하지 않는다.

배포 후 Edge 서버를 재시작하면 `voc_requests`, `voc_events`가 자동 생성된다.
사전 DB 반영용 비파괴 SQL과 API 상세는
[Edge API README](edge_api_server/README.md#실험별-voc-게시판)를 참고한다.
