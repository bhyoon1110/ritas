# v5 의뢰·시험 조회

`GET /api/v1/requests`의 기본 조회 대상은 Edge에 동기화된 의뢰 목록(`source=cache`)이다. `source=lims`는 Python → 내부 Spring → LIMS 경로를 통해 최신 데이터를 조회한다. 실시간 조회 결과는 전체 동기화 테이블과 별도로 반환한다.

| 조건 | 저장된 의뢰 | LIMS 실시간 |
|---|---|---|
| `page`, `pageSize` | 1부터, 최대 1,000건 | 동일. Spring에서는 `size`로 전달 |
| `reqNumber`, `testMtdCode` | 일치 검색 | 기본 정확 일치, `matchMode=CONTAINS`이면 부분 일치 |
| `matchMode` | `CONTAINS`는 `LIMS_LOOKUP_REQUIRED` 반환 | 미지정/`EXACT`는 기존 정확 일치, `CONTAINS`는 부분 검색 |
| `fromDate`, `toDate` | 의뢰일, 양 끝 포함 | 동일 |
| `testChargerNo`, `testChargerId` | 미지원. 명확한 오류 반환 | 시험담당자 기준, 두 조건을 함께 쓰면 AND |
| `assetNumber` | 캐시에 자산번호가 없어 `LIMS_LOOKUP_REQUIRED` 반환 | 기본 정확 일치, `matchMode=CONTAINS`이면 부분 일치 |
| `testState` | 시험 상태 코드 한 개 또는 쉼표로 구분한 여러 개 | 동일 |
| `experimentType` | 등록된 시험코드 또는 명확한 시험명으로 실험 자동 구분 | 동일 기준 적용. 장비 자산 매핑이 있으면 장비 조건도 자동 적용 |
| `includeCompleted` | `false`면 미완료 시험, `true`면 전체 상태. 상태 조건을 모두 생략하면 미완료 시험 | 실험 범위가 있으면 미완료 시험이 기본값. `experimentType` 없는 기존 API는 상태 조건 생략 시 전체 상태 유지 |

사용자가 지정한 필터는 AND로 결합한다. 관리자 매핑에서 여러 시험방법끼리, 여러 장비끼리는 OR이며, 시험방법과 장비 사이는 AND다. 응답에 `totalCount`, `source`, 기존 `items` 구조가 포함된다. 실시간 조회의 `syncedAt`은 null이며, LIMS의 값 없는 필드도 null로 전달한다. 담당자 이름에서 ID를 추정하거나 잘못된 조건을 조용히 무시하지 않는다.

FT-IR·Raman·TEM·XRD의 의뢰 선택 화면과 보고서 편집기에서는 기본적으로 **미완료 시험**(`testState=1,3,5,7`)을 조회한다. 1은 시험의뢰대기, 3은 시험의뢰, 5는 시험접수, 7은 시험중이다. 시험취소(0), 시험완료(9), 전체 상태도 선택할 수 있다. 기준 필드는 각 시험의 `testState`다. `testState`를 지정하면 상위 의뢰의 상태명과 관계없이 지정한 시험 상태를 조회한다. 미완료 조건(`includeCompleted=false`)과 취소·완료 코드를 함께 지정하면 잘못된 조합으로 응답한다.

실시간 조회의 예는 `GET /api/v1/requests?source=lims&assetNumber=ASSET-001&testState=1,3,5,7`이다. `ASSET-001`에는 실제 LIMS 자산번호를 입력한다. 하나의 시험방법에 여러 장비가 대응할 수 있으므로 자산번호는 시험방법코드나 Edge 장비코드와 독립적으로 지정한다. 미완료 시험의 장비 조건은 해당 장비로 수행할 수 있는 시험을 뜻한다. 장비 조건과 담당자·의뢰번호·기간을 조합할 수 있다.

## 설정

Python:

```properties
RIST_LIMS_REQUESTS_ENABLED=true
RIST_LIMS_REQUESTS_URL=http://127.0.0.1:8888/api/lims/requests
RIST_SSO_LIMS_INTERNAL_KEY=<Spring과 동일한 내부 전용 키>
RIST_SSO_LIMS_ALLOW_LOOPBACK_HTTP=true
```

Spring:

```properties
RITASAX_LIMS_REQUEST_PROXY_ENABLED=true
RITASAX_LIMS_SSO_INTERNAL_KEY=<Python과 동일한 내부 전용 키>
```

내부 전용 키는 32~512자의 출력 가능한 ASCII 문자열이다. 외부 LIMS 토큰은 Spring에만 설정한다. HTTP는 명시적으로 허용한 루프백 IP에만 사용할 수 있다. 다른 서버의 Spring은 HTTPS와 신뢰할 CA 설정을 사용한다. 리다이렉트는 따르지 않으며 응답은 최대 4 MiB, 페이지당 최대 1,000건으로 제한한다.

위존 회신에 따르면 의뢰조회와 두 새 조건은 개발 WAS에 반영되었다. 실제 연계 토큰과 내부 키를 설정하고 실시간 조회를 활성화한 뒤 현장에서 확인한다. 의뢰조회 응답의 `reqResultNo`는 별도 의뢰자 이메일 조회 API에 사용하는 의뢰 내부번호다.

## 보고서 화면의 의뢰 검색·선택 (2026-11-23)

FTIR·Raman·TEM의 보고서 편집 화면과 XRD의 보고서 저장·전송 화면은 같은 의뢰 선택 구성요소를 사용한다.

- 데스크톱 목록은 의뢰번호·의뢰명, 의뢰일, 의뢰자·기관, 시료, 시험명·코드, 시험 상태를 열별로 표시한다. 좁은 화면에서는 카드 형태로 줄바꿈한다.
- 시료 결과번호와 시험 결과번호가 제공되면 목록에도 표시하여 같은 의뢰번호·시료명·시험명인 항목을 구분한다. 선택 후 상세 정보에는 분석 담당자, 프로젝트, 의뢰·시료·시험 결과번호까지 표시한다. 없는 값은 추정하지 않고 `미제공`으로 표시한다.
- 검색창은 **현재 조회한 페이지(기본 200건)** 안에서 의뢰자·기관·담당자·의뢰명·시료·시험·식별번호 등을 검색한다. 공백으로 구분한 검색어는 모두 포함된 항목을 찾는다. 페이지 이동 시 검색어를 유지하며, 검색 자체로 보고서의 의뢰가 바뀌지 않는다.
- 다른 페이지는 이전·다음 버튼으로 확인한다. 전체 조회 범위를 좁히려면 위 검색 조건의 의뢰번호·기간을 사용한다. LIMS에 지원하지 않는 이름 검색 조건을 전송하지 않는다.
- 클릭 또는 방향키와 Enter로 선택하고 Esc로 목록을 닫는다. 선택한 실제 행의 의뢰번호·문서등록용 시험방법코드(`axTestMtdCode`)를 반영하며, 장비 정보가 없으면 기존 장비 입력값을 유지한다. 의뢰번호를 직접 바꾸면 이전 선택의 상세 정보도 해제한다.
- 조회 실패나 조건 변경 뒤에는 이전 결과 행을 선택할 수 없다. 검색 조건을 변경하면 이전 선택과 자동으로 채운 전송용 시험코드를 해제하고 재선택을 안내한다. 사용자가 직접 입력한 시험코드는 유지한다.

UI 표시를 공통화한 변경이며 DB 구조·SSO·메일 수신자 결정 방식은 변경하지 않는다.

검증: 관련 Python 테스트 100건, JavaScript 테스트 33건, 네 실험의 기본·구형 번들 브라우저 시나리오 8건 통과.
320·390·768·1440px 폭, 긴 시료명, 중복 의뢰번호, 의뢰자·기관 검색, 누락 값, 키보드 선택, 자동 저장 및 조회 실패를 점검했다.
브라우저 실행은 Mac Chrome과 호환 번들 기준이며, 운영 LIMS 값이나 Windows Supermium 144 실기 검증을 대신하지 않는다.

## 실험별 자동 조회 (2026-11-23)

FTIR·Raman·TEM·XRD 화면은 저장된 의뢰와 LIMS 실시간 모두 `experimentType`을 전달한다.
사용자가 의뢰번호·장비코드를 모두 적을 필요는 없다. 조건은 자동으로 적용된 실험 범위를 좁힌다.
`experimentType`은 Edge 내부에서 처리하므로 Spring/LIMS에 지원하지 않는 파라미터를 전달하지 않는다.
기존 `experimentType` 없는 API·전체 동기화·전송 인증·의뢰자 이메일 확인은 유지한다.

### 분류와 매핑

1. `RIST_REQUEST_METHOD_MAP`에 해당 실험의 시험방법을 등록했다면 **등록된 전체 목록**을 기준으로 조회한다. 이름과 무관하게 정확한 코드로 구분하며 새로운 종류는 목록에 추가한다. 다른 실험에 등록한 코드는 이름이 비슷해도 섞지 않는다.
2. 해당 실험의 조회 전용 목록이 없으면 기존 `RIST_ANALYSIS_TYPE_MAP`의 시험코드 연결을 우선 사용하고, 미등록 코드는 명확한 시험명/코드로 구분한다. 분석기 연결 설정 자체는 바꾸지 않는다.
3. 명확한 이름은 FTIR/FT-IR/적외선, Raman/라만, XRD/X선 회절, TEM/STEM/투과전자 등이다. `SYSTEM`, 일반 `X선`, `전자현미경`, `SEM-EDS` 같은 이름을 TEM/XRD로 오인하지 않는다. 여러 실험이 동시에 적힌 모호한 이름도 자동 포함하지 않는다.
4. **EDS·EDX·코팅층 이름만으로는 TEM인지 확정하지 않는다.** `TEM-EDS`, `STEM EDS`, `TEM 코팅층`처럼 TEM 종류가 명시되면 이름으로 조회한다. 나머지는 실제 시험코드를 TEM에 연결하거나 LIMS 실시간에서 TEM 장비 자산을 등록해야 한다. 실제 운영 코드 목록은 아직 제공받지 않았으므로 기본 설정은 빈 값이다.

다음은 문법 설명용 예시다. `METHOD-*`, `ASSET-*`를 실제 LIMS 값으로 바꾸고 서버를 재시작한다.
식별자의 하이픈과 앞자리 0은 유지된다. 같은 코드를 서로 다른 실험으로 중복 등록하면 설정을 거부한다.

```properties
RIST_REQUEST_METHOD_MAP=METHOD-X=XRD,METHOD-F=FTIR,METHOD-R=RAMAN,METHOD-T=TEM,METHOD-S=TEM,METHOD-E=TEM,METHOD-C=TEM
RIST_REQUEST_ASSET_MAP=ASSET-X=XRD,ASSET-T1=TEM,ASSET-T2=TEM
```

장비 자산번호는 Edge의 보고서 전송용 장비코드와 다를 수 있다. 자산 매핑은 **실시간 조회에만** 적용된다.
저장된 의뢰에는 자산번호가 없으므로 캐시와 실시간을 정확히 일치시키려면 시험방법 코드 목록도 등록한다.
사용자가 장비 조건을 직접 입력하면 자동 자산 목록 대신 그 장비로 좁혀 조회하되, 다른 실험으로 등록된 장비는 거부한다.
미등록 장비를 직접 적었다는 이유만으로 모호한 EDS 의뢰를 TEM으로 간주하지 않는다.

### 전체 건수와 처리 한도

- 시험방법 한 개로 범위가 확정되면 LIMS의 페이지 조회를 그대로 사용한다.
- 복수 시험방법·자산 조건은 서버에서 조회하고 **의뢰/시료/시험 내부번호**로 중복 제거한 후 페이지를 나눈다. 같은 의뢰번호의 서로 다른 시험은 유지한다.
- 이름 기준 조회도 LIMS의 한 페이지만 잘라 분류하지 않고 필요한 원본 페이지를 모두 확인한 뒤 전체 건수를 계산한다. 정렬은 의뢰일·의뢰번호 역순과 시료 출력 순서다.
- 스캔 방식은 요청당 최대 10,000행, 32회 호출, 새 호출 시작 기준 20초로 제한한다. 개별 호출에는 기존 연결/읽기 타임아웃이 적용된다. 조건이 너무 넓으면 `REQUEST_SCOPE_TOO_BROAD`로 기간·의뢰번호 등의 추가 조건을 안내하고 부분 성공을 반환하지 않는다.
- 조회 도중 건수 또는 동일 시험의 내용이 바뀌면 `LIMS_REQUESTS_CHANGED`로 재조회를 안내한다. 원격 실패 시 빈 목록이나 캐시 대체를 성공으로 반환하지 않는다.
- 응답의 `scopeNote`에는 코드 매핑·시험명 기준 등 현재 분류 기준을 표시한다. 화면에서도 같은 안내를 보여준다.

2026-11-23의 실험별 자동 조회 변경 자체에는 DB 마이그레이션과 Spring 수정이 필요 없다. 아래의 부분 검색 추가는 Spring 중계도 갱신해야 한다. 코드 목록이 없는 상태의 시험명 판별은 운영 LIMS의 전체 시험 분류를 보증하지 않는다.

### 2026-11-23 검증 범위

- 별도 MariaDB 11.4에서 분류 SQL, 기존 의뢰 조회 API, 시험 상태 및 페이지 처리를 확인했다. Python 회귀 묶음은 100건 통과했으며, 메일 전송 관련 2건은 수정 전 `f3d4af9`에서도 동일한 `REPORT_MAIL_INVALID`로 실패했다. 해당 2건은 이번 변경의 통과 항목에 포함하지 않는다.
- 공통 필터와 XRD 의뢰 선택 DOM 테스트 27건 통과. FTIR·Raman·TEM·XRD 각각 기본 화면과 Chrome 49 호환 번들의 브라우저 시나리오 총 8건 통과. 구형 자산 빌드는 16개 페이지의 66개 스크립트와 ES5 구문을 검증했다.
- 브라우저 실행 환경은 Mac Chrome이며, LIMS 응답은 격리된 모의 데이터다. 운영 LIMS 실연결 및 Windows의 Supermium 144 실기 검증 결과를 뜻하지 않는다. 실제 코드 목록을 확보한 뒤 운영 시료의 분류와 건수를 추가 대조해야 한다.


## 문서등록용 코드와 부분 검색 (2026-11-26 회신 반영)

강주영 책임의 2026-11-26 회신에 따라 조회 API의 `testMtdCode`와 `axTestMtdCode`를 구분한다.
Edge 응답은 표시·검색용 `testMethodCode`/`experimentCode`와 원본 `axTestMtdCode`를 별도로 제공한다.
보고서 화면은 선택한 행의 `axTestMtdCode`를 전송용 시험코드에 반영한다.
예: `A11111`(부품가공 환형)의 등록용 응답값은 `2022A11111`이다. `2022A11112`는 별도의 판형 시험이므로 대체하지 않는다.
기존 캐시에 등록용 코드가 없으면 미제공으로 표시하고 실시간 재조회를 안내한다. DB 값이나 연도를 추정하지 않는다.
실시간 의뢰조회가 활성화된 Python 큐는 저장된 조회용 코드도 해당 의뢰의 실제 응답에서 유일한 등록용 값으로 확인한다.
누락·모호·불일치·불완전한 페이지 응답은 큐 등록 전에 오류로 반환한다.

공통 검색 조건에서 **LIMS 실시간 → 부분 일치**를 선택하면 다음처럼 요청한다.

```text
GET /api/v1/requests?source=lims&matchMode=CONTAINS&reqNumber=00793
GET /api/v1/requests?source=lims&matchMode=CONTAINS&testMtdCode=A111
GET /api/v1/requests?source=lims&matchMode=CONTAINS&assetNumber=128&testState=1,3,5,7
```

- 입력한 의뢰번호·시험방법코드·장비 자산번호는 각각 앞뒤 공백 제거 후 3자 이상이어야 한다.
- `%`, `_`, 역슬래시는 일반 문자다. 클라이언트가 와일드카드를 붙이거나 SQL 이스케이프를 중복 적용하지 않는다.
- 기본은 정확 일치다. Edge의 `EXACT`는 중계 전에 생략하고 문서화된 `CONTAINS` 옵션만 LIMS에 전달한다.
- 페이지 이동에도 같은 조건을 유지한다. 검색 결과를 선택한 뒤 등록·메일에 쓰는 값은 그 행의 전체 번호와 등록용 코드다.
- 전체 의뢰 범위에서는 LIMS가 반환한 부분 검색 결과의 `totalCount`와 페이지를 유지한다.
- 현재 실험 범위에서는 필요한 원본 페이지 전체에 기존 시험방법·시험명 기준을 적용한 후 전체 건수와 페이지를 계산한다.
  부분 검색 중에는 정확 일치를 전제로 하는 자동 장비 조건을 삽입하거나 해당 장비의 모든 결과를 신뢰하지 않는다.
  모호한 시험명은 정확 검색 또는 확인된 시험방법 매핑을 사용한다.
- 기존 호출·행수·시간 상한을 유지한다. 검색이 너무 넓으면 조건 축소를 안내하며 일부 페이지만 전체 결과처럼 반환하지 않는다.

배포 시 Edge(Python 또는 Rust)와 내부 Spring 중계를 함께 갱신한다. 위존은 부분 검색을 추가했으며 개발 서버에 반영한 뒤 다시 안내하겠다고 회신했다.
따라서 코드·모의 응답 검증 완료와 외부 개발 서버 반영 완료를 구분하고, 반영 안내 후 실제 조회·문서 등록·메일 결과를 현장에서 확인한다.
